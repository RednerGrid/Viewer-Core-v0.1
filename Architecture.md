
# Viewer Architecture

Version: 0.1

---

# Цель проекта

Viewer — модульная платформа для интерактивной архитектурной визуализации.

Проект разрабатывается как долгосрочная система с упором на:

- модульность;
- простоту сопровождения;
- независимость компонентов;
- минимальный технический долг.

Главный принцип:

> Архитектура важнее скорости написания кода.

---

# Runtime

## Project Loader

Отвечает за загрузку проекта.

На входе:

```
project.json
```

На выходе:

```
project
```

---

## Scene Router

Единственная точка открытия сцены.

Отвечает за:

- переходы между сценами;
- создание context;
- запуск transition;
- создание editableScene.

Все переходы происходят только через:

```js
openScene(project, sceneId)
```

---

## Module Manager

Определяет модуль сцены.

Например:

```
panorama

object360

overview
```

Жизненный цикл любого модуля:

```
init()

↓

work

↓

destroy()
```

Модули не должны знать друг о друге.

---

# Modules

Каждый Viewer является независимым модулем.

Например:

```
Panorama Viewer

Object360 Viewer

Overview Viewer
```

Модуль отвечает только за собственное отображение.

Он не занимается:

- роутингом;
- загрузкой проекта;
- экспортом;
- редактором.

---

# Developer Tools

Developer Tools работают только в режиме

```
?dev=1
```

В публичной версии отсутствуют.

Назначение:

ускорение подготовки проекта.

На текущий момент:

- отображение координат;
- установка стартового вида;
- создание hotspot;
- экспорт сцены.

В будущем:

- редактор hotspot;
- редактор overview;
- редактор object360;
- инструменты Builder.

---

# Editor State

Во время работы редактора существует копия сцены.

```
scene.json

↓

scene

↓

editableScene
```

Редактирование происходит только через

```
editableScene
```

Исходный JSON не изменяется.

После завершения работы выполняется экспорт новой версии сцены.

---

# Builder

Builder автоматически формирует служебные данные проекта.

Текущие задачи:

- manifest;
- panorama scenes;
- object360 sequences;
- validation.

Builder не зависит от Viewer.

---

# Assets

Проект содержит только ссылки на ресурсы.

Пример:

```
assets/

panoramas/

object360/

overview/

idpass/
```

Builder автоматически находит новые ресурсы.

---

# Git Workflow

Используются две основные ветки.

```
main
```

Стабильная версия.

```
develop
```

Активная разработка.

Правила:

- одна законченная функция = один commit;
- работа ведётся только в develop;
- merge в main только после завершения группы функций.

---

# Принципы разработки

Приоритеты:

1. Простота.
2. Читаемость.
3. Минимальные изменения.
4. Отсутствие технического долга.

Не допускается:

- большие рефакторинги без необходимости;
- переименование существующих сущностей без причины;
- тесная связанность модулей.

Новая функциональность должна минимально затрагивать существующий код.

# Основной принцип проекта

Viewer — это не приложение.

Viewer — это ядро платформы.

Любая новая функция должна быть спроектирована так, чтобы через несколько лет её можно было расширять без переписывания существующей архитектуры.

Если новое решение требует переписать существующую архитектуру, сначала нужно проверить, нельзя ли встроить его в текущую систему с минимальными изменениями.
